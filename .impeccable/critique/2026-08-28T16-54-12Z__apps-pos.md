## Verdict de spécificité

POS authentiquement ancré : IDR 7 chiffres comme contrainte de composition (formatIdr, mono tabulaire, QuickPayRow.tsx:42-44 mesuré contre « Cash Exact — Rp 4.850.000 » à 390 px), touch-first réel (`data-vkp` partout), modèle de confiance encodé (comptage aveugle, tiroir seulement si cash, void PIN+motif, réimpression journalisée), offline honnête (succès AMBRE « recorded » jamais « successful », SuccessModal.tsx:311-315). Réserve : la doctrine ne se propage pas aux fichiers neufs — OrderSummaryPanel.tsx (commit 4e06714d) fait renaître 2 bugs déjà corrigés ailleurs.

**Détecteur** : 2 findings sur 491 fichiers, tous deux faux positifs (assertions/fixtures de test). Zéro hex en dur, zéro classe morte, zéro français UI en code vivant. Sondes complémentaires toutes vides.

**Navigateur** : vérifié en live — grille SOLD OUT, ajout panier, totaux PB1 cohérents (70.000 / tax incl. 6.400), terminal, fast-path EXACT + démotion du pied, undo suppression, KDS minuteurs plafonnés « 99:59+ », 34/34 boutons avec nom accessible, skip-link présent.

## Problèmes prioritaires

1. **[P1] Le récap du terminal sous-facture les combos.** OrderSummaryPanel.tsx:41-43 calcule `(unit_price + Σ modifiers) × qty` en ignorant `combo_components`, que calculateTotals.ts:54-58 (et le serveur, ADR-017) facturent. Les lignes ne somment plus au Subtotal affiché dessous. Bug déjà corrigé le 2026-07-31 dans CartLineRow.tsx:85-96, réintroduit par 4e06714d. Fix : helper domaine `lineTotalOf(item)` partagé.
2. **[P1] Le même récap affiche les lignes annulées à plein tarif.** OrderSummaryPanel.tsx:41-71 mappe `cart.items` sans filtre/style `is_cancelled` ; calculateTotals.ts:47 les exclut, CartLineRow les barre. Le client voit une ligne facturée qui ne l'est pas. Fix : aligner sur CartLineRow / SuccessModal.tsx:82.
3. **[P2] Trois noms pour un seul montant** : « Enter Amount » / « Amount Received » / « Cash Received » = trois SectionLabels pour `cashReceivedStr` (TenderDraftPanel.tsx:38, 69, 102), « Cash Received » même pour carte/QRIS. Fix : un label unique conscient de la méthode. → clarify
4. **[P2] Jargon système dans la copy caissier** : « STORE_CREDIT Exact — Rp… » (QuickPayRow.tsx:41, `toUpperCase()` de l'enum) ; « enable offline_payments_enabled (Settings → Network) » (PaymentTerminal.tsx:140) — réglage BO hors de portée du caissier. Fix : METHODS_BY_VALUE + action humaine. → clarify
5. **[P3] Ring de focus collant** CategoryNav.tsx:108 + :69 (`focus:` au lieu de `focus-visible:`) ; SuccessModal peut recevoir `cashReceived` périmé sur split (PaymentTerminal.tsx:63). → polish
